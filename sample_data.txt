[START: VARIABLES]

--- What is a Variable in Python? ---
In many languages like C++ or Java, a variable is like a physical wooden drawer. When you write "x = 5", you are allocating a physical box in memory and placing the number 5 inside it.

In Python, this is completely different. A variable is NOT a box. A variable is merely a name tag, a label, or a sticky note pointed at an object.

When you write:

x = [1, 2, 3]


Python executes two actions:

It creates a list object [1, 2, 3] floating dynamically in memory (on the heap).

It writes the name "x" on a sticky note and pastes it directly onto that list.

If you then say:

y = x


Python does NOT duplicate the list. Instead, it takes a second sticky note labeled "y" and slaps it onto the exact same physical list object!

--- Visualizing Python Sticky Notes in Memory ---

         +-----------------------------+
"x" ---> |  List Object in Memory      |
         |  Contains values: [1, 2, 3] |
"y" ---> |  Memory Address: 0x9941A2   |
         +-----------------------------+


Because both sticky notes point to the same list, any changes you make using "x" will immediately be seen when you look at "y":

# Let's test this!
x.append(4)
print(y)  # Outputs: [1, 2, 3, 4]


--- Mutability vs. Immutability ---
Every object in Python is categorized based on whether you can modify its internal values after it has been created:

MUTABLE OBJECTS (Can be changed in-place)
These are objects you can edit, add to, or shrink without changing their memory address.

Examples: Lists [], Dictionaries {}, Sets {}.

Metaphor: A mutable object is like a dry-erase whiteboard. You can write on it, wipe it off, and write something new. It is still the exact same whiteboard hanging on the same wall.

IMMUTABLE OBJECTS (Cannot be changed)
These are objects whose values can never be altered once created.

Examples: Integers, Floats, Booleans, Strings, Tuples ().

Metaphor: An immutable object is like a stone engraving. If you want to change what is written on it, you cannot erase it. You must throw it away and carve a completely new stone block.

--- Shallow Copying vs. Deep Copying ---
If you want to duplicate an object so that modifications don't affect the original:

Shallow Copy: Copies the outer container but shares references to nested children.
copylist = list(original_list)

Deep Copy: Recursively duplicates the outer container and all nested child items, ensuring 100% separation.
import copy
copylist = copy.deepcopy(original_list)

--- Interview Q&A ---
Q: What is the difference between the is operator and the == operator?
A: == checks value equality (are the contents identical?). is checks reference identity (do they point to the exact same memory address in RAM?).

--- What is a Function? ---
A function is a reusable, self-contained block of code designed to perform a single, related action. Think of a function like a kitchen blender: you put in some raw ingredients (input parameters), it runs an internal process (code execution), and it returns a completed smoothie (return value).

In Python, functions are First-Class Objects. This means they are treated with the exact same capabilities as variables, numbers, or strings:

You can assign a function to a variable.

You can pass a function as a parameter into another function.

You can return a function from another function.

--- Scope Resolution and the LEGB Rule ---
Every time you refer to a variable name inside a function, Python searches for that name in a strict hierarchical order:

LOCAL (L): Looks inside the currently running function first.

ENCLOSING (E): Looks inside the outer parent function (if dealing with nested functions).

GLOBAL (G): Looks at the module level (the top of your .py file).

BUILT-IN (B): Checks Python's internal library (like print, len, range).

--- Override Keywords: global vs nonlocal ---

global: Tells Python to bind a local variable name directly to the top-level script, allowing you to update global variables.

nonlocal: Used inside nested functions to update a variable residing inside the parent function's scope.

--- Nested Closures: Functions that Remember State ---
A closure is a special pattern where an inner nested function is returned from an outer parent function, and it "remembers" the local variables of its parent function even after the parent function has finished executing.

Metaphor: Think of a closure as a functional backpack. When the parent function packages and returns the child function, it packs up all enclosing variables the child needs and hooks them directly onto the child's back.

--- Simple Code Example ---

def make_multiplier(factor):
    # Enclosing parent variable
    def multiply(number):
        # Child nested function remembers 'factor'
        return number * factor
    return multiply

double_engine = make_multiplier(2)
triple_engine = make_multiplier(3)

print(double_engine(10)) # Output: 20
print(triple_engine(10)) # Output: 30

[START: LISTS]

--- What is a List? ---
A list is an ordered, changeable (mutable), and flexible collection of elements defined with square brackets [].
Under the hood in CPython, a list is implemented as a contiguous array of object pointers. It does not store raw values directly; it stores a sequence of 64-bit memory addresses pointing to where the objects live on the heap.

--- Performance Profiles ---

Append: $O(1)$ amortized constant time.

Index Lookup: $O(1)$ constant time (calculated directly via offset pointer math).

Insert/Delete: $O(N)$ linear time (because all trailing items must physically shift in memory).

--- Simple Code Examples ---

# Creating a list
my_list = ["apple", "banana"]

# Appending (Runs in constant O(1) time)
my_list.append("cherry")

# Changing an element by index
my_list[0] = "peach"
print(my_list) # Output: ['peach', 'banana', 'cherry']

[START: TUPLES]

--- What is a Tuple? ---
A tuple is an ordered, unchangeable (immutable) sequence of elements defined using parentheses ().

--- Key Structural Differences: Lists vs. Tuples ---

Immutability: Once a tuple is constructed, its size and elements are permanently locked. You cannot append, remove, or reassign elements.

Memory Efficiency: Lists over-allocate empty space to support fast future appends. Tuples are sized precisely at allocation, wasting zero bytes of RAM.

Speed: Because tuples are static, Python allocates them in a single memory block, making them significantly faster to load and look up than lists.

Data Integrity: Tuples are ideal for write-protecting safe data that must never change during execution (like database credentials, API configurations, or GPS coordinates).

--- Simple Code Examples ---

# Initializing an immutable tuple
dimensions = (1920, 1080)

# Attempting to modify raises a TypeError
# dimensions[0] = 1280 # ERROR!

# Unpacking values cleanly
width, height = dimensions
print(f"Resolution: {width}x{height}") # Output: Resolution: 1920x1080

[START: SETS]

--- What is a Set? ---
A set is an unordered collection of unique elements defined using curly braces {}. Sets are governed by two strict properties:

No Duplicates: If you add the same value multiple times, the set discards the duplicates and preserves exactly one.

Fast Membership Testing ($O(1)$ Complexity): Sets are implemented using Hash Tables. When you search for an item inside a set (item in my_set), Python computes the hash of the item and goes directly to its indexed memory slot. Lookups run in constant time, whereas lists require scanning elements sequentially in linear time.

--- Hashability Rule ---
Only immutable, hashable objects (like strings, integers, and tuples) can be added to a set. You cannot add mutable items (like lists) because their values can change, which would break the hash index lookups.

--- Simple Code Examples ---

# A set automatically filters out duplicates
numbers = {1, 2, 2, 3, 3, 3}
print(numbers) # Output: {1, 2, 3}

# High-speed membership checking (O(1) complexity)
print(2 in numbers) # Output: True

# Set operations (Union and Intersection)
set_a = {1, 2, 3}
set_b = {3, 4, 5}
print(set_a | set_b) # Union: {1, 2, 3, 4, 5}
print(set_a & set_b) # Intersection: {3}

[START: DICTIONARIES]

--- What is a Dictionary? ---
A dictionary is an associative key-value map defined using curly braces with colons (e.g., {"key": "value"}).

Keys must be Hashable: Dictionary keys must be immutable objects (like strings, integers, or tuples). You cannot use a list as a key because its value can change, causing lookup failures.

Quick Lookups: Like sets, dictionaries are powered by hash tables, ensuring key lookups run in $O(1)$ amortized constant time.

--- Simple Code Examples ---

# Creating a dictionary
user_profile = {
    "username": "alex_dev",
    "status": "online"
}

# Accessing values safely using .get() to prevent crashes
status = user_profile.get("status")
theme = user_profile.get("theme", "dark") # Defaults to "dark" if key is missing

print(status) # Output: online
print(theme)  # Output: dark

[START: OOP]

--- What is Object-Oriented Programming (OOP)? ---
OOP is a software design style that structures programs around modular, real-world data blueprints (Classes) and physical instances (Objects). Think of a Class as a blueprint for a smartphone, and an Object as the actual physical phone built in the factory from that blueprint.

Python implements OOP through four core pillars:

INHERITANCE (Reusing Code):
Allows a new class (child) to inherit and reuse methods and variables from an existing class (parent), eliminating duplicate code.

Metaphor: A parent class is a template. The child class copies the template but can add custom functions of its own.

Code Example:

class Animal:
    def __init__(self, name):
        self.name = name
    def eat(self):
        return f"{self.name} is eating."

class Dog(Animal):  # Dog inherits everything from Animal
    def speak(self):
        return f"{self.name} says Woof!"

buddy = Dog("Buddy")
print(buddy.eat())    # Outputs: Buddy is eating. (Inherited!)
print(buddy.speak())  # Outputs: Buddy says Woof! (Customized!)


POLYMORPHISM (Many Forms, Same Interface):
Polymorphism (literally "many forms") allows different classes to implement methods with the exact same name but distinct logic.

Metaphor: A physical "Power Button" is polymorphic. On a computer, it boots the CPU; on a toaster, it heats coils; on a car, it starts the engine. It is the same interface but different operations occur.

Code Example:

class Dog:
    def speak(self): return "Woof!"
class Cat:
    def speak(self): return "Meow!"

def make_animal_sound(animal):
    print(animal.speak()) # Polymorphic call

make_animal_sound(Dog()) # Outputs: Woof!
make_animal_sound(Cat()) # Outputs: Meow!


ENCAPSULATION (Hiding & Protecting Data):
Encapsulation wraps data inside a class and restricts outside code from directly accessing or modifying internal variables.

Implementation: Private variables are declared with a double underscore prefix (e.g., self.__balance). Outside scripts cannot access or modify these values directly, preventing data corruption.

Code Example:

class BankAccount:
    def __init__(self, balance):
        self.__balance = balance # Private variable
    def get_balance(self):
        return self.__balance # Controlled Getter
    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount # Controlled Setter with safety guard

account = BankAccount(100)
# print(account.__balance) # ERROR! Raises AttributeError.
account.deposit(50)
print(account.get_balance()) # Outputs: 150


ABSTRACTION (Hiding Complexity):
Abstraction hides complex background operations and displays only simple, essential interfaces to the user.

Metaphor: When you press the gas pedal in a car, you accelerate. You do not need to understand combustion or fuel injectors. The pedal is the abstract interface.

Code Example:

from abc import ABC, abstractmethod

class RemoteControl(ABC):  # Abstract Base Class
    @abstractmethod
    def press_power(self):
        pass

class TVRemote(RemoteControl):
    def press_power(self):
        return "TV turned on."

[START: DECORATORS]

--- What is a Decorator? ---
A decorator is like a wrapper. It allows you to inject extra behaviors before or after another target function executes, without modifying the target function's code.

--- Metaphor ---
Think of a decorator as a protective waterproof phone case. Your raw phone can make calls. By wrapping it in the case, it can still make calls, but it has gained a new "waterproof" feature without you modifying any internal circuits of the phone.

Under the hood, applying a decorator with the @ syntax is just shorthand for functional re-assignment:
my_func = my_decorator(my_func)

--- Simple Code Example ---

from functools import wraps

# 1. Defining the decorator function
def log_decorator(original_function):
    @wraps(original_function) # Preserves original function name & docstrings
    def wrapper(*args, **kwargs):
        print(f"[TRACE] Executing '{original_function.__name__}'...")
        result = original_function(*args, **kwargs) # Runs the actual function
        print(f"[TRACE] Execution completed.")
        return result
    return wrapper

# 2. Applying the decorator using the @ symbol
@log_decorator
def greet(username):
    print(f"Hello, {username}!")

greet("Alex")

[START: MEMORY]

--- CPython Memory Management ---
Memory allocation and deallocation in Python is fully automated. CPython manages memory using two main background systems:

Reference Counting:
Every object on the heap contains an integer counter called ob_refcnt in its header. This counter tracks how many variable names, list items, or dictionary keys point to it.

When reference count increases (+1): Assigning the object to a new variable name.

When reference count decreases (-1): A variable goes out of scope, is reassigned, or is deleted.

Deallocation: The exact millisecond an object's reference count hits 0, Python instantly frees its memory.

Generational Garbage Collector (GC):
Reference counting has one blind spot: Circular References. This happens when object A points to object B, and object B points back to object A, but both are disconnected from your actual program variables. Their reference counts remain stuck at 1, causing a memory leak.

How it works: The GC periodically sweeps memory using three generational queues (Gen 0, Gen 1, Gen 2). It detects isolated circular reference loops, breaks the loops, and reclaims the leaked RAM.

--- Small Integer Caching Optimization ---
To maximize speed and save memory, Python pre-allocates and caches an integer pool ranging from -5 to 256 during startup. Whenever you reference an integer in this range, Python reuses the exact same cached heap addresses.

--- Simple Code Example ---

# Small Integer Caching Test
x = 100
y = 100
print(x is y) # Outputs: True (Both refer to the exact same cached address!)

a = 300
b = 300
print(a is b) # Outputs: False (Address is different; 300 is outside the cache range)

[START: GENERATORS]

--- What is a Generator? ---
A generator is a special type of function that evaluates and yields elements "lazily" (on-demand) one-by-one, instead of calculating the entire list in advance and storing it in your computer's RAM.

--- Yielding vs. Returning ---

The return keyword sends back a final result and completely destroys the function's execution frame and local variables.

The yield keyword pauses the function, saves its exact local variable state, passes back the current value, and waits. When you call next(), the function resumes on the exact line after the yield!

--- Memory Efficiency Comparison ---
If you need to process a 10GB log file:

List Comprehension (Eager): Reading all lines into a list loads all 10GB into your RAM immediately, crashing your program if it runs out of memory.

Generator (Lazy): Yielding line-by-line keeps only the single active line in memory. Your RAM usage remains constant at just a few kilobytes.

--- Simple Code Examples ---

# 1. Defining a Generator Function
def simple_counter():
    print("Run 1 starting...")
    yield 1 # Pauses and yields 1
    print("Run 2 starting...")
    yield 2 # Pauses and yields 2

counter = simple_counter() # Creates generator, does not run code yet
print(next(counter)) # Outputs: Run 1 starting... followed by 1
print(next(counter)) # Outputs: Run 2 starting... followed by 2

# 2. Memory Comparison of List vs Generator
# List: Allocates 1 million square numbers in RAM immediately
squares_list = [x**2 for x in range(1000000)]

# Generator: Occupies virtually zero RAM, calculating values on-the-fly
squares_generator = (x**2 for x in range(1000000))
